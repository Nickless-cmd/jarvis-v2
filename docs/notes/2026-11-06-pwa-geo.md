# PWA-lokation: geo-opslag via API (6/11-2026)

Hullet: alle tre lokationskilder i Desk gik gennem `window.jarvisDesk.geo`
(Electron-preload). I PWA'en findes broen ikke, så browser-GPS fik et fix men
blev kasseret, fordi label-opslaget (reverse) fejlede.

Ændring:
- `apps/api/jarvis_api/routes/geo.py`: `GET /geo/reverse` og `GET /geo/search`
  — kun en ny indgang til `_osm_reverse_geocode` / `_osm_geocode` (throttle +
  User-Agent genbrugt). Label = «vej, by», som Electron-broen.
- `deskLocation.ts`: `geoBridge()` er en kæde — Electron-broen når den findes
  (uændret sti), ellers `/geo`-ruterne. Arlington-værnet er urørt: accuracy
  > 50 km eller tom label giver stadig null; fejler API'et, kasseres fixet.

Bevidst IKKE gjort:
- Ingen `/geo/ip`: ip-api uden klient-IP giver SERVERENS adresse (Svendborg for
  alle). Kræver X-Forwarded-For gennem pfsense + Caddy — separat opgave.
  IP-tilstand giver derfor stadig null i web.
- Browser-GPS i laptop-browser er WiFi-triangulering; på telefon (standalone
  PWA) er det ægte GPS. ÅBENT spørgsmål til Bjørn: kun telefon, eller også
  laptop-browser? Svaret afgør om der skal et troværdighedsværn mere ind.

Ikke leveret her (uden for scope): Desk-versionsbump, `jarvis-desktop-v<version>`-
tag og `desk-release`-CI. Begge builds (`build:web`, `build:renderer`) og
`deskLocation.test.ts` (15 tests) er grønne lokalt.
