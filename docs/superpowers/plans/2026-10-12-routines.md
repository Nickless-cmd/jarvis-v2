# Routines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace autonomous chat sessions with private, user-controlled routines whose definitions, isolated runs, delivery, diagnostics, migration, API, and Desk UI share one governed lifecycle.

**Architecture:** A new Routine domain owns definitions, immutable versions, fenced runs, events, deliveries, inbox policies, and quarantine records in SQLite. A session-neutral agentic kernel is extracted from the visible-run stack and used by both chat and routine adapters; routine results flow only through the run recorder and delivery outbox, while a separate diagnostic projector may send only the content-free failure projection to the owner/Jarvis app session. A dedicated `/api/routines` surface and a global Desk `routines` surface enforce the same authorization service.

**Tech Stack:** Python 3.11, SQLite, FastAPI/Pydantic, pytest, React 19, TypeScript, Vite/Vitest, existing Jarvis Desk CSS tokens.

**Spec:** `docs/superpowers/specs/2026-10-12-routines-design.md`

## Global Constraints

- A routine/run is never a chat session and has no `chat_session_id`, transcript, or session-derived continuity.
- Routine result delivery must never call `append_chat_message()` or use `session_inbox`.
- The only session write allowed by this program is the redacted operational failure projection produced by `routine_diagnostics`; it targets `resolve_owner_app_session()`, never an external/member session, and contains none of the forbidden fields from spec §8.
- `owner_user_id` is always a canonical `users.user_id`; Discord IDs and arbitrary legacy strings are resolved, never copied.
- Owner and Jarvis cannot list, open, search, or mutate another user's private routine content. They may see only the redacted failure projection.
- `system_owner` routines are inspectable only by the owner role; all other routines are inspectable only by their canonical human owner.
- Unknown ownership, identity ambiguity, missing structured recipient evidence, and test-like IDs fail closed into inert migration quarantine.
- Stop, pause, archive, and delete remain distinct. Stopped routines auto-archive after 30 inactive days; automatic hard deletion is opt-in only.
- Three consecutive execution failures pause a routine by default; cancellation, skipped triggers, and delivery-only failures do not count.
- Every state mutation is atomic, versioned where applicable, and idempotent under retries.
- New secrets are forbidden. Sensitive routine fields and event payloads are encrypted with the owner's existing key.
- Desk must reuse existing theme tokens/components in dark, light, and high-contrast modes.
- Boy Scout rule applies before logical edits to `visible_runs.py`, `prompt_contract.py`, or `heartbeat_runtime.py`: extract the nearest natural unit first and preserve re-exports.
- Use `/opt/conda/envs/ai/bin/python` for Python verification and the repository attribution wrapper for every commit.

## Review Focus

1. A bearer token may carry either a canonical account ID or a legacy Discord ID; both must converge to one canonical principal, while unknown or multiply matched identities return unauthorized.
2. Lease loss or cancellation between `tool_requested` and the tool receipt must never replay an effect or allow the stale generation to append events.
3. Adversarial failures containing names, paths, secrets, instructions, tool arguments, stack traces, or output must yield the same fixed-schema redacted projection on both inbox and shared-session surfaces.
4. Legacy rows with empty stamps, mixed identity formats, creator/recipient disagreement, or test-like IDs must produce non-empty quarantine and must never be silently assigned.
5. An edit racing an active run must leave the run on its immutable old version while the UI shows the new version and preserves paused/stopped state unless the user explicitly reactivates.
