# Struktur-vagterne — de pytest-tests der håndhæver husets egne regler.
#
# Kilden er denne fil. CI læser den (.github/workflows/ci.yml → python-vagter),
# og peger en linje på en fil der ikke findes, fejler pytest med exit 4 — så
# listen kan ikke rådne tavst.
#
# HVORFOR IKKE HELE tests/:
#   Målt 20/9-2026: hele suiten (1540 testfiler) nåede 1% på 18 minutter. Den
#   kan ikke køre i CI. Disse filer er de statiske vagter: ingen DB, intet
#   netværk, ~35 sekunder tilsammen.
#
# HVORFOR HER OG IKKE KUN I PRE-COMMIT:
#   pre-commit kører 16 script-vagter (scripts/verify_*.py) — men ikke én af
#   dem er pytest. Og pre-commit kan springes over med `git commit --no-verify`.
#   Det kan dette job ikke. Det var præcis derfor push-vejen kunne ligge død i
#   uger: vagten fandtes, og testen der fangede fejlen fandtes — ingen kørte den.
#
# HVORFOR test_docs_drift_check.py IKKE ER MED:
#   Målt 20/9-2026 i et rent venv med requirements.txt installeret: appen
#   importeres fint, men monterer kun 77 routes mod 612 i det fulde miljø —
#   router-sættet afhænger af hvad der er tilgængeligt. Generatoren falder
#   derfor tilbage til AST (600 routes) og sammenligner mod en doc skabt med
#   608. Testen er miljø-følsom og ville være rød fra dag ét i CI.
#   Den er ikke ubevogtet af den grund: pre-commit-hooket «Docs drift» kører
#   samme check lokalt, hvor det fulde miljø findes.
#
# Føj en vagt til ved at skrive dens sti her. Testene skal være statiske:
# ingen database, ingen netværkskald, ingen tunge fixtures.
